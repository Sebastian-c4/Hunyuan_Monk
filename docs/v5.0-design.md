# 混元武僧 v5.0 设计方案（EEex 版）

> 定稿日期：2026-11-27
> 状态：设计已定，切片 A 已出代码
> 适用范围：`c4Monk` 组件 1（ADD_KIT 主组件）

---

## 1 目标与非目标

**目标**

1. v5.0 **硬依赖 EEex**（安装时检查，缺失则警告/失败）。
2. 技能点相关的机制全部搬离全局脚本：升级发放、点数记账、加点交互。
3. 队友（Player2~6）选了混元武僧同样生效——不依赖"和主角在同一张地图"。
4. 一套图形界面：剩余点数、已加总数、各技能当前等级一目了然，并可直接加点。

**非目标**

- `ensure_fist` / `ensure_helm` 暂不动（继续留在 observer 鸟上，见 §9）。
- 洗点 / 重置：不做（将来可以加"重置"按钮，退点 + 施放 opcode 172 清选择器）。
- 对话 fallback：不做。对话彻底退役（§4）。

## 3 现状 → 目标

现在这条链（`baldur.bcs` → 6 只 observer 鸟 → 鸟的 BCS）：

```
baldur.bcs
 └ InPartyAllowDead(PlayerN) + Kit(PlayerN,c4Monk)
    └ CreateCreatureImpassable → c4MonkP1..P6.cre
         └ c4MonkPN.bcs
              ├ ×50 ensure_fist.baf     ← 保留
              ├ ×1  ensure_helm.baf     ← 保留
              ├ ×1  start_dialog.baf    ← 删除
              └ ×25 add_skill_point.baf ← 删除
```

失效原因：`baldur.bcs` 只在玩家 AI 脚本运行时执行；队伍分处不同地图、过场、对话期间，队友对应的鸟不跑 → 该角色的升级加点丢失。这是"某些地图不生效"和"偶发丢点"的根源。

v5.0 之后：

| 机制 | 新实现 | 依赖脚本 |
|---|---|---|
| 升级加点 | CLAB 偶数列 `AP_C4MKSP%i%` 施放 `c4mksp%i%.spl`（1 条 `309 Set c4mkspg` + 1 条 `309 Increment c4mkspl`） | 无 |
| 点数记账 | 2 个 Locals：高水位 + 剩余缓存（见 §5） | 无 |
| 开页面 | 先天能力 `c4mkski1.spl` 内 opcode 402 → Lua `C4MKUI` | 无 |
| 加点 | UI 点击 → Lua 校验 → `ReallyForceSpellRES` | 无 |
| 拳头/头盔修正 | observer 鸟（保留） | baldur.bcs |

## 5 数据模型（角色 Locals）

**v5.0 只剩 1 个点数变量**，所有变量名都 ≤8 字符（能直接塞进 opcode 309 的 resource 字段）：

| 变量 | 取值 | 含义 |
|---|---|---|
| `c4mkspg` | 0..25 | **已发放总数的高水位**。CLAB 在偶数级 `Set` 成 `i/2`，只增不减 → 某一级漏发，下一级会自动补齐 |

技能线等级（切片 E 已统一改成短名）：

| 变量 | 取值 | 含义 |
|---|---|---|
| `c4mkbd` | 0..5 | 身法等级 |
| `c4mkbdx` | 0/1 | 高等身法已学（HLA `AP_C4MKBDX` 自带发放效果后置位） |
| `c4mkbdxm` | 0/1 | 身法满 5 级时已打上 HLA 前置标志 `AP_C4MKBDX0`（面板补发老存档用，不参与计算） |
| `c4mkm1` ~ `c4mkm4` | 0/1 | 心法四条 |
| `c4mkf1` ~ `c4mkf7` | 0..5 | 七条拳法（`f6` = 穿心；原 `PiecingFist` 拼写已修正） |
| `c4MonkCheck` | 0/1 | 是混元武僧（由 `AP_C4MK00` 的 `c4mkchek` 效果写入，待验证） |

派生值（**不落盘**）：

- 已花费 `spent` = `c4mkbd` + 4 条心法 + 7 条拳法；**高等身法不计入**（它来自 HLA，不消耗点数）
- 剩余点数 `left` = `c4mkspg - spent`，由 `C4MK_Left()` 现算，负数归 0

**没有"剩余点数"变量了**：对话退役后没有触发器需要读常量门槛，UI 直接算，所以不存在"点数与账面不符"这类 bug。

**拼写修正（v5.0）**：`PiecingFist` → `PiercingFist`，随变量短名一起改成 `c4mkf6`。法术 resref `c4mkf6a..e` / 物品本来就没有拼写错误，不受影响；5.0 不保证旧档兼容，不需要做变量迁移。

**为什么这么设计**（替代原来的 25 个 flag）：

- 原方案的 25 个 `c4MonkAddSkillPoint%i%` 是"漏发补齐"兜底；补齐只需要"发放量随等级单调"这一条性质，**一个高水位变量就够了**
- `Set` 语义还顺带挡住了"等级吸取再升回来"导致的重复发放
- 剩余点数从"存"改成"算"，无法记错
- 变量总数 38 → 13（12 条线 + 1 个发放高水位）

**过渡期的取舍**：`c4mkspl` 之所以还存一份缓存，是因为**对话的触发器不会做减法**（`GlobalGT` 只能比较常量）。等 UI 接管加点、对话退役后，可以把 `c4mkspl` 彻底删掉，改成纯函数 `left = c4mkspg - spent`。

## 6 加点规则（从旧 `.d` 提炼，UI 必须照搬）

| 技能 | 最高 | 前置 |
|---|---|---|
| 身法 1~5 | 5 | 角色等级 ≥ 6 / 12 / 18 / 24 / 30，逐级 |
| 高等身法 | 5（一次性） | 已在 HLA 界面选过 `AP_C4MKBDX`；**不消耗点数** |
| 心法 1~4 | 各 1 | 等级 ≥ 0 / 8 / 16 / 24，顺序解锁 |
| 拳法 1~7 各 5 级 | 各 5 | 无前置，纯点数 |

### 身法的"三选一"（已定：UI 只显示一条总技能）

身法本身是一个**主动技能**：`c4mkbd%i%-` 是选择器，使用时从 铁布衫 / 真元护体 / 天罡战气 三个里选一个（opcode 214 + `c4mkbd%i%.2da`）。所以：

- UI 上「身法」只显示**一条**，数值 = `c4MonkBodyTraining`（0~5），不需要知道每级选了哪一个
- UI 加一级 = 施放/发放 `c4mkbda-`~`c4mkbde-` 中对应的选择器，玩家自己点选三选一
- **不做** `c4MonkBodyChoice%i%` 这类额外记账（2026-11-27 与作者确认：三选一是技能使用时的一次选择，不属于加点记录）

**拳法改名（2026-11-27，作者定稿）**：七条拳法统一成**两个字**的名字（去掉了"拳"字，简洁有力），整份 tra 全局替换（说明正文、分级标签 `@1111..`、状态提示 `@1561/@1571`），代码注释同步：

命名逻辑：`<元素或质感>+<部位/动作>`，与 `c4mkf1..7` 的伤害类型一一对应（寒/火/电/酸/砍/穿刺/加速）。

**名称来源**：面板从 tra 取 strref（`@200/@2007/@311..@314/@1100..@1700`），Lua 里只留同名兜底，两边不会再出现两个名字。

**悬停提示**（`tooltip lua "C4MK_Tip('f1')"`，写法见 `X-Option.menu` 里 `text` 带 `tooltip lua` 的例子）：

```
冰魄    3 / 5
下一级：花 1 点（第 4 级）

冰魄：寒冷伤害。每次命中有5%/8%/13%/21%/34%概率缓慢敌人，持续6/9/12/15/18秒。
```

提示由三部分组成：名称+进度、下一级的花费与等级要求（不可加时附原因）、技能说明（tra 原文）。

说明文本按行拆分、按需精简，避免悬停框占满屏幕：

| 行 | 说明来源 | 备注 |
|---|---|---|
| 混元身法 | `@321`（v5.0 新增的精简版） | 长版 `@209` 仍保留给法术描述 |
| 高等混元身法 | `@2008` | |
| 心法四条 | `@317`~`@320`（v5.0 新增，逐条一条） | 原来四合一在 `@310`，整段太长 |
| 拳法七条 | `@1101` `@1201` … `@1701` | 原本就是单段 |

说明文本通过 `sp_ui.tph` 在安装时把上述条目解析成 strref，注入 `M_C4MKT.lua`（`COPY ... EVAL`），所以换语言会自动跟着变；注入失败时 `M_C4MK.lua` 退回内置中文名。

技术要点：

- 资源：`override/c4mksp.menu`（**纯文本** MENU，参照 `EEex/copy/override/B3Timer.menu`），`Infinity_PushMenu("C4MonkSp_Menu")` 打开
- 动态数值：`text lua "C4MK_Text('f1')"`；每行是独立的 `text` 元素（带 `action` 加点、`enabled` 置灰、`tooltip lua` 说明），不再用 `list`
- 文本注入：`override/M_C4MKT.lua` 由 `sp_ui.tph` 用 `COPY ... EVAL` 生成，内容是 tra 条目解析出的 strref；`M_C4MK.lua` 通过 `Infinity_FetchString` 取文本
- 缩放：坐标按 1024×768 设计，缩放在 Lua 里用 `EEex_Menu_ScaleX/Y` 处理（`EEex_Menu.lua:37/49`）
- 关闭：菜单写 `ignoreesc`，用显式关闭按钮 → `Infinity_PopMenu`，避免 ESC 弹出后状态不同步
- 图标 resref（≤8 字符）：身法 `c4mkbd`（与特技图标同一个）、高等身法 `c4mkbdb`（金星）、
  心法 `c4mkm1b`~`c4mkm4b`（兜帽 / 云 / 莲 / 眼，按各自效果设计）、拳法 `c4mkf1b`~`c4mkf7b`
  （雪花/火苗/闪电/骷髅/长剑/心+箭/漩涡）；面板底板 `c4mkspbg`（820×344 不透明）。
  全部 32×32 单帧，由 `tools/make_ui_icons.py` 生成（`--preview` 出预览图）。
- 切片 A 先用现有的 `c4mkbd1d` / `c4mkskib` 等 BAM 占位

## 8 事件流

```
升级
  CLAB[列 i, i 为偶数] = AP_C4MKSP%i%
    → 引擎施放 c4mksp%i%.spl（只有一条效果）
        → 309 Set c4mkspg = i/2     （高水位，漏发的级会被补齐）
    （无脚本、无 EFF 文件参与）

选高等身法 HLA
  HLA 表里的 AP_C4MKBDX = c4mkbdx.spl
    → 5×172 清掉 a~e 身法选择器
    → 5×171 发 5 个 c4mkbdx-
    → 177→EFF 置 c4mkbdx = 1（UI 显示"已学"）
    （无脚本参与；不再走"1→2→3"的对话流程）

身法修满 5 级（高等身法的前置）
  luc4monk.2da: AP_C4MKBDX 的 PREREQUISITE = AP_C4MKBDX0
    → c4mkgb5.spl 额外带一条 313（High-Level Ability Denotation, resource=C4MKBDX0）
        → 角色身上记下"已获得 AP_C4MKBDX0"，高等身法才在 HLA 界面出现
    → 旧档（v5 之前就满级、身上没标志）：打开面板时 C4MK_EnsureBodyHLA()
      补发一次 c4mkbdx0，并置 c4mkbdxm=1 防重复
    （v4.5 是对话里 ReallyForceSpellRES("c4mkbdx0") 做的；对话退役时漏搬，已补回）

打开页面
  玩家使用先天能力「技能学习」(c4mkski1.spl)
    → 402 InvokeLua → C4MKUI(op402, sprite)
        → C4MK_Open(sprite)：刷新汇总 → Infinity_PushMenu

加点
  点击行 → C4MK_Buy("f1")
    1. 校验：剩余 > 0？未满级？等级门槛？
    2. SetLocal(c4mkf1 +1)（剩余是派生值，不需要减）
    3. EEex_Action_ExecuteResponseStringOnAIBaseInstantly(
         'ReallyForceSpellRES("c4mkf1a",Myself)', sprite)
       └─ 拳法各级是"替换"：法术开头的 5×321 先清掉本线 a~e 的旧效果
          （248 近战效果 / 278 命中 / 73 伤害），再挂当前级的
    4. C4MK_Refresh()：汇总数字立即刷新
```

## 14 待办：踢出重招后的被动翻倍（先测再改）

### 已知现象

作者自建的剑圣（Kensai）kit 实测过：**角色开除出队再重新加入时，kit 被动会随机性地翻倍，有时又恢复正常**。

### 机制拆解（两个独立开关）

1. **加入时会不会重放 CLAB** —— IESDP 在 EFF parent resource 字段明确写着（`IESDP.md:94937`）：passive kit bonuses 若作为 V2 effect 烘焙进可招募 CRE，必须把 parent resource 设成对应 AP 法术，否则加入队伍时"**due to CLAB processing**"会被再应用一次。
2. **重放时旧效果会不会被清掉** —— 取决于效果有没有 parent resource（= 当初施放它的 SPL resref）。有则引擎能去重，没有就叠加。

"随机"的来源：开关 1 受"NPC 等级 vs 队伍等级"影响（只有等级不足才触发自动升级），开关 2 受效果是否带 parent resource 影响；两者组合出"有时翻倍、有时正常"。

### 本 mod 的暴露面（2026-11-27 用 `ni info` 核对）

| 法术 | 效果 | 重放后果 |
|---|---|---|
| `c4mkac0.spl` | opcode **0 AC bonus**（每级 +1，25 个 header） | **会叠加**，与剑圣同类 |
| `c4mkbf1.spl` | opcode **111 Create weapon** → `C4MKBF1.ITM` | 可能再造一个拳头，当前只靠 `ensure_fist.baf` 的 `HasItem` 兜着 |
| `c4mksp%i%.spl` | opcode **309 Set** | 不叠加（Set 幂等）✅ |
| `c4mkspl` | 309 Increment | 会虚增，靠 `C4MK_Sync` 修（见 §5） |

### 检查清单（进游戏十分钟）

准备一个 12 级混元武僧，记下 AC / 先天能力列表 / 背包拳套数，然后：

1. 踢出队伍 → 存档 → 读档 → 重新招募（**中间不让队伍升级**）→ 再记一遍
2. 把队伍练一级，重复第 1 步

判读：

- 第 1 步就翻倍 → 开关 2 失败（去重没生效）
- 只有第 2 步翻倍 → 开关 1 的自动升级路径在重放 CLAB
- 都不翻倍 → 引擎去重正常，本 mod 无需处理

辅助命令（对比招募前后的角色效果）：

```powershell
$env:NI_GAME = 'C:\robovoid\tools\ni_test\BG2EE'
ni info <角色文件名>.CRE        # 看 V2 Effects 里是否出现重复的父资源
```

### 若确认翻倍，两种修法

**修法 1（推荐）**：给 CLAB 用的每个 AP 法术**开头加一条 `opcode 321`**（Remove effects by resource），resource 指向自己 → 重放时先清旧再加，天然幂等。`lib/body_training.tph` 里已经在用这个套路（`CLONE_EFFECT ... opcode=321`），只是没用到 AP 法术上。

**修法 2**：按 IESDP 的建议，只给"烘焙进 .cre 的被动"补 parent resource。对玩家用 Keeper 改出来的角色无效。

**前置条件**：两种修法都依赖"321 能清除同一资源的效果"这一语义，必须先实测确认，再决定改哪个。

### 鸟的碰撞（未解决，也是回退 A1 的原因）

CRE 上已挂 opcode 287，但它只是去掉**选择圈**，物理占位一直在——所以不管生成在哪里，最后都可能挡路。

要真正减小占位，用 opcode 342「Animation: Override Data」：`Field=4` 覆盖 personal space，`Value` 取 1（最小）。**`Value=0` 不能用**——IESDP 警告它会导致该生物**无限攻击/施法距离**，也会让别人从任意距离锁定它。

这一条没有实施：`342` 在 CRE 上烘焙是否对现有动画生效、`Value=1` 的实际手感，都需要进游戏看。若要做，改 `_functions.tpa` 里创建 `c4MonkPN.cre` 的那段，加一条 `ADD_CRE_EFFECT opcode=342 parameter1=1 parameter2=4 timing=9 target=1`。
